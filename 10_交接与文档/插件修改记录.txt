---------- 2.1 plugin_init / plugin_cfg ----------

做了啥:
  plugin_init:
    注册 say/say_team: signup/报, cancel/退, aistart/开赛, aitype/赛制,
                       aiabort/停赛, aivote/投
    register_clcmd say / say_team -> aiSayHandle  (抓赞助者输入)
    loadSkillMaps()
    1秒循环 taskSignupHud
  plugin_cfg:
    换图会重载整个插件, 内存全丢。
    所以读 PDS_GetCell("ai_pending_start"), 有值才调 onMapChange()。
    SQL 没就绪则 Local_GuestInit() (stock, 曾经漏写 stock 关键字导致编译失败)。

为什么:
  换图 = 插件重载。不用 PDS 的话, 选好地图 changelevel 后报名状态全没。


---------- 2.2 菜单: showMainMenu / showTypeMenu ----------

做了啥:
  主菜单全部走 ai_lang() -> HnsLang_Get(id, key), 不再硬编码中文。
  第3项 AI_MENU_TYPE = 「HNS比赛选择」, 点开 showTypeMenu:
    娱乐局 / 赞助局
  点完不关菜单, 回到 showMainMenu。
  盗版玩家 (isGuestPlayer) 禁止选赞助局。

为什么:
  用户要 AI 菜单跟 /lang。
  用户要新增娱乐局/赞助局选择。
  用户要菜单点完不关。


---------- 2.3 权限: isUserVipOrAdmin ----------

做了啥:
  项目里没有独立 isUserVip。
  用 isUserWatcher / isUserAdmin / is_user_admin 合成 isUserVipOrAdmin()。
  强制开赛、改类型、改人数、取消报名、选模式、选地图、填赞助者都走这个。

为什么:
  用户说 VIP 或管理员优先选模式/地图/赞助者。


---------- 2.4 收团上场: closeSignup / taskPlacePlayer / moveToTeam ----------

做了啥:
  closeSignup:
    过滤掉线 -> 人数不够且非强制则继续报名
    否则 SIGNUP_CLOSE, 全员 moveToSpec, 1秒1人 taskPlacePlayer
  taskPlacePlayer:
    上场完:
      如果 g_bPendingMatchStart (换图回来) -> 直接 startMatch
      否则 beginPostGroupSetup (先选模式再选地图)
  moveToSpec / moveToTeam:
    用 rg_set_user_team, 不用 rg_internal_cmd("jointeam")

为什么:
  以前强制开赛: closeSignup 把人拉观战, 再用 jointeam 上场。
  LOBBY 下 blockCmd 拦截 jointeam, 人就卡在观战, 也不选模式地图。
  这是用户说「强制开启为啥给我拉到观战去了就没了」的根因。


---------- 2.5 分组后选择: beginPostGroupSetup / 投票 / 地图 ----------

流程:
  beginPostGroupSetup
    有 VIP/管理员 -> showRulesMenu (MR/计时/决斗)
    没有 -> startRulesVote
  VIP 选完模式 -> beginMapSelect
  beginMapSelect
    有 VIP -> showMapChoiceMenu: 随机 / 指定 /maps / 当前地图
    没有 -> startMapVote (skill 地图列表)
  afterMapChosen
    赞助局 -> beginSponsorInput
    娱乐局 -> startMatch

投票显示:
  formatex(szItem, ..., "%s \r[%d%%]", 名字, 百分比)
  效果: 1. hns [100%]   百分比红色
  先模式后地图。cmdAiVote 按 g_eVoteKind 打开对应投票菜单。

为什么:
  用户原话: 报名结束之后先分组然后让玩家投票或者优先vip管理员选当前打什么模式
  比赛和随机地图还是指定地图/maps还是当前地图, 投票长这样 1.hns [100%]
  百分比是红色的, 先选比赛模式后选地图。


---------- 2.6 赞助者输入: beginSponsorInput / aiSayHandle ----------

做了啥:
  地图选定后如果是赞助局:
    找第一个在线 VIP/管理员
    messagemode 打开聊天输入
    g_bSponsorNameInput[id]=true, AI 自己的 say 钩子吃掉这句话
    30秒超时 taskSponsorTimeout, /取消 跳过
    名字 trim, 去掉 %, 调 hns_external_set_sponsor_name
    然后 startMatch

为什么:
  用户要赞助局开启、报名结束分配队伍后, 管理员或 VIP 输入比赛赞助者是谁。
  不能用 cmds.inc 里的 g_bSponsorNameInput, 那是 System 自己的, 互不覆盖。


---------- 2.7 startMatch / 换图 PDS ----------

做了啥:
  非当前图:
    PDS_SetCell("ai_pending_start", 1)
    同时存: ai_picked_map, ai_match_rules, ai_sponsor_match,
            ai_sponsor_name, ai_force_start, ai_team_size
    server_cmd("changelevel %s", g_szPickedMap)
    return
  当前图:
    hns_external_set_team_size
    hns_external_set_match_mode
    赞助局且有名字则 hns_external_set_sponsor_name
    hns_begin_external_match
    清 g_bForceStart / g_bPostGroupSetup / g_bWaitingSponsor / g_bPendingMatchStart
    PDS_SetCell("ai_pending_start", 0)
    g_eState = MATCH_RUNNING

onMapChange (下班前刚改):
  如果 PDS pending=1:
    恢复规则/赞助/地图, 5秒后 taskPendingResume
    rebuildSignupFromOnline (用当前在线玩家重建名单, 原名单换图会丢)
    closeSignup 再上场, 然后因为 pending 直接 startMatch
  如果不是 pending (普通换图 / 管理员换图 / 地图投票换图):
    以前: SIGNUP_OPEN + 2分钟冷静期, 人够自动收团开赛
    现在: 报名清空, g_eState=SIGNUP_IDLE, 不自动报名, 不开赛

abortSignup 也会清 ai_pending_start=0, 避免下次换图误触发。

为什么:
  用户最后说: 切换地图不开启比赛ai报名。
  pending 例外必须留: 否则 AI 选指定地图后 changelevel, 比赛永远开不起来。


---------- 2.8 HUD / 报名人数显示 ----------

以前:
  HUD: 报名: n/12
       012345[6]78910     (当前人数用 [] 标出)
  聊天: 已报名 n 人 | 服务器在线 n 人 | 012345[6]78910
  函数 buildSignupBar()

现在 (下班前按用户要求取消数字条):
  HUD 只在 SIGNUP_OPEN 显示: 报名: n/12
  聊天: 已报名 n 人 | 服务器在线 n 人
  buildSignupBar() 已删除

为什么:
  用户先抱怨「聊天框的X人数不见了012345678910」, 当时加了明文数字条。
  后来又说「把ui的那个12345678910取消掉」, 所以删掉。
  颜色码以前可能导致聊天显示成空格, 所以现在不用颜色码拼数字条。


---------- 2.9 语言化 ----------

做了啥:
  stock ai_lang(id, key, out, len) -> HnsLang_Get

  菜单标题、按钮、投票标题、地图选项、HUD 都走语言键。

3. source\HnsMatchSystem.sma
============================================================

plugin_init 新增 register_native:
  hns_ai_enter_lobby            -> native_ai_enter_lobby
  hns_external_set_sponsor_name -> native_external_set_sponsor_name
  hns_begin_external_match      -> native_begin_external_match
  (hns_external_set_team_size / hns_external_set_match_mode 本来就有)

native_ai_enter_lobby:
  仅当前是 MODE_TRAINING 才 lobby_start(), 返回 1/0
  native_set_mode 故意不加 MODE_LOBBY, 大厅只能由比赛流程激活

native_external_set_sponsor_name:
  读字符串, trim, 去掉 %
  写 g_szSponsorName
  在线玩家名字匹配则设 g_iSponsorPlayer, g_iSponsorGC=clamp(hns_gc_get_player,5,20)
  g_bPersistentSponsor=true

native_begin_external_match:
  设 MATCH_TYPE_SPONSOR 或 MATCH_TYPE_CASUAL
  开赛前把当前所有 T/CT 标 g_ePlayerInfo[id][PLAYER_MATCH]=true
  并写 PLAYER_TEAM
  然后 mix_start()

为什么:
  mix_start 里 forceUnmatchedToSpec 会把没标参赛的人踢观战。
  AI 上场后如果不先标记, 开赛瞬间全员又回观战。
  这是强制开赛「拉观战就没了」的第二层原因。

9. 代码损坏事故 (必须写进记录, 避免再犯)
============================================================

对同一个 SMA 做重叠 patch (连续 replace 同一区域) 会把文件截断。发生过:

  1. onMapChange 变成 }eState  函数头被吃掉
  2. rebuildSignupFromOnline 尾巴混入冷静期代码
  3. loadSkillMaps 被 buildSignupBar 截断, fclose 丢失
  4. 语言文件 en/ru 插进 REG_SIGNUP 中间
  5. Local_GuestInit 缺 stock 关键字

修法:
  读整段, 一次性替换, 禁止对同一区域连续重叠 patch。
  PowerShell 不要用 here-string 写 SMA。
  改完读函数头尾确认括号配对, 再编译。
